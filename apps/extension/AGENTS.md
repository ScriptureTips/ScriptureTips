# @scripturetips/extension

The browser extension (vision §3.6): the rewrite of v1.0.3 (`../ScriptureTips-BrowserPlugin`, live on the Chrome Web Store), shipped as an update to the same listing. It builds on `@scripturetips/scripture-links`, the core the website plugin uses.

- **Content script** (`src/content.ts`): in every page and frame (`<all_urls>`, `all_frames`, Google left out as v1.0.3 did), it links the references in the body and shows the passage on hover or tap. It stays out of sites the reader turned off, the ScriptureTips site itself, and pages that aren't `http(s)`. Its links carry `data-st-owner="extension"`, so a site's own plugin and the extension each show their own tooltip, never two, and only its links get v1.0.3's small logo after them (`static/content.css`, `static/mark.png`), so the reader can tell the extension made them. The logo is the one web-accessible file, by extension URL: a page's content security policy blocks a `data:` image, but not that. The build sets the URL's scheme for each browser; the browser fills in its ID (`__MSG_@@extension_id__`, the internal UUID in Firefox). Passages are fetched by the background (`viaBackground`). The reader's translation choices are kept in the extension's own storage, one entry per site (`choices:<host>`), never in the site's `localStorage`. Settings changes apply to open pages at once.
- **Background** (`src/background.ts`): a service worker in Chrome, an event page in Firefox. It fetches only the API's `/widget/` routes, and on install saves the settings, carried over from v1.0.3 on an update (v1.0.3 reset them on every update; this never does).
- **Settings** (`src/settings.ts`, sync storage key `settings`): where links go (the ScriptureTips reader, the default, or an outside site with a URL template and its own translation code), the tooltip's translation, the link generator's format, the sites turned off, and another ScriptureTips address (a satellite). `migrate` reads v1.0.3's keys (`BibleServices`, `defaultBibleService` as a place or, after a v1.0.3 slip, a URL, `defaultMode`, `tipDisabledDomains`), which are left in place.
- **Pages** (`static/`, `src/popup.ts`, `src/options.ts`, `src/tool.ts`): the popup (the logo, a red-left/green-right slide switch for this site beside its name, two 80px cards to the tool and settings), the settings page (over the clouds-and-birds artwork, with the logo and the credits the artwork's CC BY-NC license asks for; `static/brand/clouds-and-birds.svg` is a copy of `apps/web/public/brand`'s), and the link generator (HTML, BBCode, wiki, Markdown; references already linked are left; undo and redo).
- **Manifest** (`src/manifest.ts`): one source, a manifest per browser. **Permissions never grow beyond v1.0.3's** (`storage`, `activeTab`; v1.0.3 also had `tabs`): Chrome turns an update off until each user approves new ones. `manifest.test.ts` holds this. The version must stay above 1.0.3.
- **Build:** `./toolbox pnpm --filter @scripturetips/extension build` writes `dist/chrome` and `dist/firefox` (load unpacked, or zip for the stores). `ST_SITE` sets the reader its links open (the dev stack, `https://dev.scripturetips.com`, if not set; `https://scripturetips.com` in production) and `ST_DATA` the data server passages are read from (the dev stack's `https://dev.scripture.tips` if not set; `https://scripture.tips` in production; vision §7.2). The settings' other ScriptureTips address (a satellite) changes only the reader: passages still come from the data server (sources.md §8 item 34). The extension stays out of both sites' own pages. No dependencies beyond esbuild: the extension APIs used are typed by hand in `src/browser.ts`.
- **Icons** are v1.0.3's (the commissioned logo, docs/branding.md). UI text is NZ English, in the pages and `_locales/en` (Chrome has no `en_NZ`).
- **Not built yet:** the note composer and insert flow, sign-in and the user's own compilation (they wait for notes and accounts in the extension, stage 4), the local cache of passages (sources.md §8 item 29), translating the UI, Safari, and Edge testing.

**Link generator window** (`src/generator.ts`, `src/generator-window.ts`): the popup's Generator card sends `open-generator` to the tab (`tabs.sendMessage`; falls back to opening `tool.html` in a tab where that fails), and the content script's top frame opens the generator as a window on the page: a shadow-root host in the page's own tree, reset inline with `!important` like the tooltip's, px sizes and its own font, draggable by the title bar and resizable by the corner (pointer capture; arrow keys on the grip; `fit` keeps it in the page, 340x380 at least), its frame kept in `storage.local` under `generatorWindow`. `generator.ts` holds the form's markup and logic, shared with the `tool.html` page. Help: `link-generator`.

**Text size** (`src/text-scale.ts`): the footer of the toolbar popup has magnifying glasses (`popup.ts`) that step the text of the passage tooltips on pages through 85%, 100%, 115%, 130%, 150%, 175% and 200% (`textScale` in `@scripturetips/scripture-links`, which multiplies every text size by `--st-text-scale` on the tooltip's own host). Only the tooltip: the popup, the settings page and the link generator keep their size. It is kept in `storage.local` under its own key (per device, not synced: a desktop's size is wrong on a phone), not in `settings`, so a click doesn't make every open page scan again; the content script applies it with `setPreferences({ textScale })`. The page's own text is left alone. Help: `text-size`.

**Demo pages** (`demo/`, served at https://dev.scripture.tips/demo/ by the development stack's Caddy only, never in production): ordinary pages written like other people's sites, with no ScriptureTips script, for trying the extension and for the store screenshots. `jonah.html` is a blog entry with some 70 references in many forms, an author's own link, code and a field. A build for the dev stack treats `/demo/` on the data server as an ordinary page (`ST_DEMO`, `demoPath` in `build.ts`, `leftAlone` in `src/settings.ts`; the extension otherwise leaves the data server alone); a release build has no such exception. Tests: `src/demo.test.ts`, `src/settings.test.ts`, and the demo spec in `apps/web/e2e/extension.spec.ts`.

**Help:** every feature built here is documented, with screenshots, on the `scripture.tips` site before it is done (`apps/site/AGENTS.md`: topic, screenshot script, version folder). Its topics are what a later in-extension help icon will link to, so a topic's id never changes.

Tests: `./toolbox pnpm --filter @scripturetips/extension test` (settings and migration, the link generator, the manifest, the bundle); in a browser, `apps/web/e2e/extension.spec.ts` (build first; desktop only).
